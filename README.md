# Эйдос · интерактивные листы

**Тильзит Драгунатори / Мастер стоек** и **Смарчок / Грибной симбионт** для авторской RPG «Эйдос». React + TypeScript + Vite, локальное сохранение и отдельные механики персонажей. Тильзит использует интерактивный пергаментный лист с перемещаемыми разделами и простыми бросками; прежний лист Смарчка сохраняет физические 3D-кубики.

## Запуск

Node.js 20.19+ или 22.12+ (проверен Node 24).

```sh
npm ci --ignore-scripts
npm run dev
```

`--ignore-scripts` исключает интерактивный postinstall библиотеки Dice-Box. Скрипты `predev` и `prebuild` сами копируют её проверенные npm-ресурсы в `public/dice-assets/`. Они не требуют CDN, ключей или внешнего сервера. Обычный `npm ci` также работает, но postinstall Dice-Box ожидает ввод или свой таймаут.

```sh
npm run typecheck
npm test
npm run build
npm run test:browser
```

Браузерные тесты запускаются последовательно: Тильзит на отдельном Vite 4182, затем общая регрессия и Смарчок на 4179. Каждый тест останавливает свой сервер. Нужен Chromium: `/usr/bin/chromium` или путь в `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Для готовой сборки задайте `EIDOS_TEST_URL` с адресом и нужным подпутём.

## Тильзит · этап 1

Десять настоящих HTML-разделов: характеристики, здоровье и бой, стойки, навыки, атаки, способности, снаряжение, броски, история и заметки. Режим «Настроить расположение» включает выделенные ручки перемещения и изменения размера. Перенос мышью или касанием переставляет блок на место целевого блока; сетка перепаковывает разделы без перекрытий. При переносе к краю окна страница прокручивается. Стрелки на ручке перемещают блок, на углу — меняют размер. На телефоне ширина блоков занимает доступную область, изменяется высота. Сворачивание доступно и в обычном режиме.

Порядок, размеры и свёрнутое состояние сохраняются в `eidos:layout:tilzit:v1`. «Сбросить раскладку» меняет только расположение. Отдельный подтверждаемый сброс персонажа сохраняет раскладку и Смарчка.

Новый лист начинается с имени Тильзит Драгунатори, прозвища Белый Узник, расы Голиаф, класса Воин / Мастер стоек, HP 12/12 и скорости 6 клеток. Значения характеристик: 15, 12, 14, 10, 13, 8. Их модификаторы вычисляются через `floor((score - 10) / 2)` и отдельно не записываются. Старые значения, имя, предметы, заметки, раунд и расход действий сохраняются в прежнем ключе Воина; ранее заданные независимые модификаторы заменяются вычислением из сохранённого значения согласно требованиям Тильзита.

Урон, лечение и прямое HP редактируются с ограничениями 0 / максимум. Последнее фактическое изменение HP показано в блоке. Временные HP не добавлены: в правилах проекта их нет. Защита всегда определяется активной стойкой: Щит 15, Дуэлянт 10, Натиск 12. Идентификатор прежней стойки assault и её подтверждённые боевые правила сохранены; при смене стойки прежняя ручная Защита очищается.

Простые броски: d4, d6, d8, d10, d12, d20, d100, 1–30 кубиков, модификатор, проверки по нажатию, преимущество / помеха для d20. Используется равномерный `crypto.getRandomValues` с rejection sampling. Оба натуральных d20, выбранный результат, модификатор и итог видны в результате и последних 10 бросках. Режим d20 не применяется к урону и сырому парированию; подтверждённая помеха щита имеет приоритет. Успех без сложности не определяется.

Подтверждённые атаки щитом и мечом сохраняют расход действий, отдельное подтверждение попадания и бросок урона. Можно задать полный бонус, формулу вида `2d6 + 1` и тип вручную. Дополнительные пользовательские атаки — свободные броски без придуманного расхода действий. Способности сохраняют раскрываемое описание, условия и ручной счётчик, если игрок задал ресурс. Правила списания для пользовательских способностей не выдуманы.

История персонажа содержит редактируемые возраст 34 года, рост 248 см, вес 215 кг, клан Драгунатори, предысторию и цели. Инвентарь поддерживает CRUD, количество и раскрываемое описание. Заметки и прежний журнал / NPC доступны отдельно.

Утверждённая иллюстрация Тильзита, три изображения его стоек и предыстория в доступных файлах отсутствуют. Оставлено место для загрузки статичного портрета, история пустая. Бонусы навыков и типы урона не назначаются по классу. Карточки Лудика, Бонобу-Бату и Кайра найдены среди встроенных изображений прежних PDF и изучены как визуальные референсы; их механики не переносятся Тильзиту.

`src/tilzit/CharacterPresentation.tsx` задаёт отдельный интерфейс статичного представления и событий стойки, урона, лечения, атаки и защиты. Анимация, риггинг и подмена внешности не подключены.

Прямая ссылка использует `?character=tilzit`; `?character=smarchok` открывает Смарчка. Выбор в переключателе обновляет адрес и сохраняется после reload.

## Лист и сохранение

У Тильзита редактирование доступно в самих разделах. У Смарчка «Редактировать лист» сохраняет прежние независимые характеристики и модификаторы. Максимум HP можно менять; навыки имеют явно введённый полный бонус, владение не добавляется автоматически.

Предметы, журнал, NPC / связи, навыки, история и тела открываются поверх листа. Инвентарь поддерживает поиск, количество, категории, описание, заметки и экипировку. Портрет PNG / JPEG / WebP до 1 МБ кадрируется через `object-fit: cover`.

Каждый персонаж сохраняется в отдельном ключе `eidos:sheet:<id>:v2`. Старое сохранение Воина `v1` переносится автоматически, включая незавершённые атаки и расход действий. «Сбросить персонажа» требует подтверждения и затрагивает только выбранный лист. Данные остаются в этом браузере; серверной синхронизации нет. Ошибка localStorage показана явно. Повреждённая JSON-запись сохраняется в `<key>:recovery`, прежде чем лист восстанавливает исходные значения. Неизвестная версия структуры не перезаписывается.

## Смарчок

Сам гриб всегда имеет **1 HP**. Здоровье, Защита и Скорость сверху относятся к **Туше**. Исходная карточка не задаёт HP Туши, уровень, Защиту, Скорость и запас / максимум Мицелия: они оставлены пустыми для игрока. Характеристики и явно напечатанные бонусы навыков взяты из предоставленной карточки; их можно менять.

- Поднять мертвеца: 5 Мицелия, существующее целое тело или новая пользовательская запись нежити. Лимита количества тел нет.
- Регенерация: 1 Мицелий = 1 фактически восстановленный HP, без кубиков. Не превышает максимум.
- Поле: ручное вложение X. Размер и дебафф не вычисляются без закреплённых правил.
- Связь / Считывание / Запугивание: 1 / 2 / 3 Мицелия. Считывание даёт только текущую мысль.
- Переработка: вручную выбранная добыча; целое тело становится переработанным и недоступным для поднятия или повторной переработки.
- Тела и нежить: имя, описание, необязательные HP, заметки и состояние. Бой за нежить не автоматизируется.

При нехватке Мицелия действие заблокировано, ресурс не расходуется. Переполнение запаса не уничтожает тело: игроку предложено скорректировать максимум или количество. Кошелёк, инвентарь и сюжетные записи изначально пусты.

## Воин

Сохранены щит (15 Защиты, помеха 2d20, d4 + текущая СИЛ), дуэлянт (10, меч d8 + СИЛ, рукопашное парирование), штурм (12, меч и щит, одно добивание после убийства основной атакой). Игрок / мастер подтверждает попадание, толчок и реакции. Успешное парирование даёт немедленную ответную атаку; натуральная 20 делает ответ критическим. Критический урон задаётся вручную: формула не закреплена.

Подготовка, расход основного / бонусного / реакции, бесплатные триггеры и незавершённые действия сохраняются. Reload не восстанавливает действия. Новый раунд очищает триггеры; отмена незавершённого действия требует подтверждения. Дополнительный бонус атаки, владение, сложности и типы урона не выдуманы.

## Настоящие 3D-броски Смарчка

`@3d-dice/dice-box` 1.1.4: Babylon.js визуализирует модели, Ammo WASM в worker вычисляет движение, вращение и столкновения. После остановки движок считывает грань через collider face map и ray casting. Итог рассчитывается только из этих результатов. Предварительно выбранных значений в визуализатор не передаётся.

Свободный лоток Смарчка: d4 / d6 / d8 / d10 / d12 / d20, количество каждого, смешанный пул и модификатор. Его проверки и навыки используют один движок. После завершения лист остаётся доступным; «Убрать кубики» очищает поверхность. Защита от повторного запуска и таймаут не допускают ложных результатов.

**WebGL обязателен для 3D Смарчка.** Тильзит работает без WebGL. Скрытый RNG fallback библиотеки отключён предварительной проверкой: при отсутствии WebGL показана ошибка, история и действия не меняются. Браузерные тесты действительно бросают физические кубики Смарчка (SwiftShader на тестовой машине) и проверяют диапазоны, пул и арифметику; RNG не подменяется.

Технический предел одного визуального броска — 30 кубиков; это ограничение производительности, а не игровое правило. История хранит последние 10 бросков отдельно для каждого персонажа.

## Архитектура

| Модуль                           | Назначение                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------------- |
| `src/state/core.ts`              | Общие редактируемые данные, валидатор, versioned persistence и generic mechanic plugin |
| `src/dice/DiceProvider.tsx`      | Единственный физический движок, асинхронные броски и overlay                           |
| `src/components/Collections.tsx` | Общие редакторы, инвентарь, журнал, NPC и навыки                                       |
| `src/mechanics/warrior/`         | Боевые правила Воина и его интерфейс                                                   |
| `src/mechanics/smarchok/`        | Мицелий, способности, целые / переработанные / поднятые тела                           |
| `src/state/persistence.ts`       | Проверка боевой сессии Воина и миграция v1                                             |
| `src/App.tsx`                    | Выбор персонажа и общая композиция листа                                               |
| `src/tilzit/`                    | Новый лист, сетка, простые броски, данные и интерфейс будущей анимации                    |

Следующий персонаж получает собственный plugin состояния и компонент механик, сохраняя общий лист, коллекции и движок. Универсальная ресурсная полоска не навязывается.

## GitHub Pages

```sh
npm run build -- --base=/EidosD-D/
```

Публикуется **содержимое** `dist/` вместе с `.nojekyll` в существующую `gh-pages`. Модели, текстуры и WASM располагаются под тем же подпутём `/EidosD-D/dice-assets/`; загрузки с CDN нет.

Оригинал Смарчка предоставлен пользователем (`public/reference/smarchok.jpg`). В интерфейсе отображается только SVG-область портрета, не изображение всей карточки в качестве фона. Остальная карточка — интерактивные HTML-компоненты. Dice-Box распространяется по MIT; копия лицензии включена в статические ресурсы.
