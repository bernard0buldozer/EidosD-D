# Эйдос · Интерактивный лист персонажа

Первая рабочая версия листа **Воина 1 уровня, Мастера стоек** для авторской RPG «Эйдос». React + TypeScript + Vite. Полностью локальное приложение: без сервера данных, аккаунтов и чужих игровых правил.

## Запуск

Нужен Node.js **20.19+ или 22.12+**; в облачной среде проверен Node.js 24.

```sh
npm ci
npm run dev
```

Vite сообщает адрес в терминале. Для production:

```sh
npm run build
npm run preview
```

Содержимое `dist/` можно размещать на статическом хостинге. Если нужен подпуть, задайте его при сборке, например `npm run build -- --base=/eidos/`.

## Что работает

- Все шесть характеристик: отдельные натуральный d20, модификатор и итог.
- HP от 0 до 12, стойка и связанные Защита/оружие/атаки.
- Щит: прозрачная помеха (два d20, выбирается меньший), d4 + 2, подтверждение толчка и прикрытие союзника.
- Дуэлянт: одна реакция за раунд, подтверждаемое мастером парирование, немедленный ответ, критический ответ при натуральной 20.
- Штурм: одна дополнительная атака за бонусное действие после убийства основной атакой; цепочка не продолжается.
- Свободная подготовка, разрешённые бонусные и бесплатные смены, расход действий, новый раунд.
- Раздельные стадии атаки и урона, 2D-кубики, последние десять бросков.
- Имя, портрет (PNG/JPEG/WebP до 1 МБ), кошелёк и заметки; localStorage с версией и проверкой данных.
- Адаптация для планшета, desktop и телефона; на телефоне — быстрый результат броска и нижняя навигация.

HP, стойка, **расход действий, незавершённые действия и триггеры**, история, заметки и портрет переживают обновление страницы. Reload не восстанавливает потраченные действия. При недоступном хранилище приложение продолжает работать и сообщает, что изменения не сохранены.

## Как играть

Выберите стойку в подготовке. «Начать бой», атака или реакция переводят лист в бой. После броска атаки подтвердите попадание или промах по решению мастера. При попадании отдельно бросьте урон и завершите атаку, отметив убийство/успешный толчок, если применимо. Только после этого открываются соответствующие триггеры. Ответ после парирования нужно разрешить до смены стойки.

Одна бесплатная смена расходует свой триггер, а обычная разрешённая смена — бонусное действие. «Новый раунд» очищает триггеры и восстанавливает действия. «Выйти из боя» явно возвращает подготовку; сброс требует подтверждения.

## Проверки

```sh
npm run typecheck
npm test
npm run build
npm run test:browser
```

Браузерный тест сам запускает и останавливает отдельный dev server. Он использует системный `/usr/bin/chromium`, если доступен; можно задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. На другой машине установите браузер командой `npx playwright install chromium`. Для проверки уже запущенного dev server или production preview задайте `EIDOS_TEST_URL`.

```sh
EIDOS_TEST_URL=http://127.0.0.1:4173 npm run test:browser
```

`artifacts/` содержит свежие скриншоты 1440, 1024, 768, 390 px и JSON-результат браузерных сценариев. Этот каталог не коммитится. Браузерные тесты используют изолированные профили и не меняют игровой localStorage пользователя.

## Архитектура

| Модуль                            | Ответственность                                                                   |
| --------------------------------- | --------------------------------------------------------------------------------- |
| `src/data/warrior.ts`             | Данные первого героя, без JSX                                                     |
| `src/domain/types.ts`             | Общие характеристики, ресурсы, состояние персонажа и результаты бросков           |
| `src/domain/dice.ts`              | RNG, вычисление результата, ограниченная история; без визуализации                |
| `src/mechanics/warrior/config.ts` | Стойки и явные неизвестные правила                                                |
| `src/mechanics/warrior/rules.ts`  | Чистый reducer, действия, разрешения и триггеры Воина                             |
| `src/mechanics/warrior/*.tsx`     | Специальный игровой интерфейс Воина                                               |
| `src/state/useSheet.ts`           | Композиция общего состояния и механики первого героя                              |
| `src/state/persistence.ts`        | Версия localStorage, восстановление и проверка данных                             |
| `src/components/`                 | Общие характеристики, показатели, портрет, визуализатор кубиков, история и диалог |
| `src/App.tsx`, `src/styles/`      | Компоновка и адаптивный пергаментный интерфейс                                    |
| `tests/`                          | Правила, сохранение и реальные браузерные сценарии                                |

Общий `CharacterDefinition` **не содержит стоек, парирования или добивания**. Для нового героя создайте отдельные данные и модуль механики с собственными состоянием, reducer и панелями. Подключите его в композиции листа, переиспользуя общие компоненты и dice engine. Выберите отдельный ключ persistence и соответствующую схему проверки. Не добавляйте Ци, Мицелий и другие классовые правила в reducer Воина. Классовые ресурсы опциональны; у первого героя ресурс не задан и не отображается.

## Неопределённые правила

В `src/mechanics/warrior/config.ts` отмечены `TODO: rule not defined by game design`:

- дополнительный бонус атаки / владение: бросается **только известная часть d20 + СИЛ (+2)**;
- модификатор и сложность парирования: бросается только натуральный d20, успех подтверждает мастер; физический d20 можно ввести вручную;
- формула и сложность толчка: успех подтверждается вручную;
- формула критического урона: критический урон вводится вручную, кубики не удваиваются автоматически;
- типы урона меча/щита, навыки и владения не заданы;
- общие последствия натуральных 1/20 атак не заданы: показаны натуральные результаты без автоматического успеха, провала или критического урона. Исключение — явно заданная натуральная 20 парирования.

Перемещение показано как скорость 6 клеток; дополнительных правил расходования перемещения нет. Не добавлены смерти, отдыхи, слоты, состояния, временные HP и прочие механики D&D.
