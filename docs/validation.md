## Браузерные сценарии

1. Страница и первый Воин открываются; доступна клавиатурная навигация и справка.
2. Все шесть характеристик бросаются; натуральный кубик, положительный/нулевой/отрицательный модификатор и итог проверены отдельно.
3. HP уменьшается и увеличивается, не выходит за 0–12, сохраняется после reload.
4. До боя стойки выбираются вручную без расхода; Защита равна 15 / 10 / 12.
5. В бою смена без триггера заблокирована; меч в Стойке щита недоступен.
6. Щит бросает два d20; оба видны, минимум выбран, основной слот потрачен.
7. Незавершённая атака и расход действий сохраняются после reload.
8. Попадание → отдельный d4/d8 + 2 → завершение атаки; подтверждённый толчок открывает бесплатную смену.
9. Бесплатная смена не тратит бонус; последующая бонусная смена тратит его и закрывает дальнейшие обычные переключения.
10. Прикрытие тратит реакцию; успешное прикрытие даёт бесплатную смену; смена стойки не восстанавливает реакцию.
11. Дуэлянт парирует один раз за раунд. Неудача тоже расходует реакцию.
12. Натуральная 20 парирования даёт критическую ответную атаку без расхода основного/бонусного действия; критический урон введён вручную.
13. До немедленного ответа стойка не переключается; после ответа доступна бесплатная смена.
14. Физический d20 парирования вводится вручную. Пустой результат нельзя подтвердить как успешный; введённое, но не использованное значение очищается при новом раунде.
15. Штурм не предлагает парирование или прикрытие. Убийство основной атакой открывает добивание за бонусное действие; после дополнительной атаки цепочка закрыта.
16. Новый раунд восстанавливает слоты и очищает триггеры; для отмены незавершённого действия требуется подтверждение.
17. История обновляется и очищается; стойка и Защита восстанавливаются после reload.
18. Имя, кошелёк, заметки и загруженный портрет сохраняются; портрет можно удалить.
19. Телефон сразу показывает компактный результат броска; нижняя навигация перемещает к бою.
20. При ошибке localStorage приложение остаётся рабочим и показывает честный статус отсутствия сохранения.

Браузерные тесты управляют RNG только в изолированном тестовом браузере для воспроизводимых проверок. Код приложения использует `crypto.getRandomValues` с rejection sampling. В unit-тестах также проверен реальный RNG для d4, d8 и d20.

`artifacts/browser-results.json`, `artifacts/accessibility.json`, `artifacts/sheet-*.png`, `artifacts/roll-*.png`, `artifacts/mobile-roll-feedback.png`, `artifacts/assault-combat.png`, `artifacts/shield-after-parry.png` созданы текущими проверками и не добавлены в Git.


Для проверки production:

```sh

# В другом терминале:
EIDOS_TEST_URL=http://127.0.0.1:4173 npm run test:browser
```

## Границы автоматизации

Оставлены явно неопределённые правила: дополнительный бонус атаки и владение; модификатор/сложность парирования; сложность/формула толчка; формула критического урона; типы урона и список навыков. Решения мастера подтверждаются вручную. Бросок атаки считает только заданную часть d20 + СИЛ.

Сохранены черновики `install_script` и `start_skill`, а также необходимые домены исследований. Это сохранение конфигурации, а не её применение или публикация. Для использования подготовленного снимка в будущих облачных задачах пользователь должен сохранить настройки и опубликовать среду. Новая задача после публикации в рамках этой работы не запускалась.
