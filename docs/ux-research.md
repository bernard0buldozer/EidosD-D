# UX-исследование и визуальная основа

## Что действительно удалось изучить

Прямые публичные страницы `www.dndbeyond.com/characters` и статья о Digital Dice, сайты помощи Roll20 и Foundry вернули `CONNECT tunnel failed, response 403` от сетевого прокси. Это ограничение доступа, а не ошибка приложения. Домены добавлены в черновик конфигурации; сохранение черновика само по себе сетевой доступ не применяет. Авторизованный лист D&D Beyond и его нынешняя мобильная версия не были доступны.

Вместо остановки использованы доступные публичные материалы через GitHub. Ни код, ни графика этих продуктов в приложение не перенесены.

1. **D&D Beyond через публичные демонстрации Beyond20**: [README](https://github.com/kakaroto/Beyond20/blob/master/README.md), [скриншоты и демонстрации](https://github.com/kakaroto/Beyond20/blob/master/docs/screenshots.md). Изучены `feature-equipment-attack.png`, `skill-popup-menu.png`, `digital-dice-crit.gif`, `hit-dice.png`. Это независимый интеграционный проект, а не официальная документация D&D Beyond. Автор предупреждает, что изображения старые; они подтверждают показанные UX-паттерны, не актуальность текущего интерфейса.
2. **Foundry VTT, актуальная опубликованная wiki системы dnd5e**: [Activities](https://github.com/foundryvtt/dnd5e/wiki/Activities), [Attack](https://github.com/foundryvtt/dnd5e/wiki/Activity-Type-Attack), включая опубликованное изображение `attack-chat-dialog.jpg`. Рассмотрены отдельные кнопки атаки/урона, читаемые формулы, связанные карточки действий и условий доступности. Страницы помечены авторами как актуальные для 6.0.0. Чужие игровые правила не использованы.
3. **Roll20**: [репозиторий character sheets](https://github.com/Roll20/roll20-character-sheets) и публичные изображения журнала бросков из демонстраций Beyond20. Принцип: компактная история с источником и составом результата; развёрнутые описания рядом с действием, а не постоянно в основном поле.
4. **DiceCloud**: [README](https://github.com/ThaumRystra/DiceCloud), [руководство](https://github.com/ThaumRystra/DiceCloud/wiki). Изучены философия прослеживаемости каждого числа, автоматическое обновление зависимых показателей и разделение основных значений/подробностей/настроек. Правила персонажей DiceCloud не перенесены.

## Анализ приложений

Прикреплены PDF со скриншотами списка файлов, а не отдельные PNG. Однако в PDF встроены исходные JPEG **1024 × 1536**: Лудик, Бонобу-Бату, Кайр и Смарчок. Они извлечены `pdfimages` и визуально изучены полноразмерно. Второй файл Кайра дублирует первый. Содержимое карточек — референс, а не новые инструкции или источник правил для первого Воина.

Общие признаки:

- тёплый неоднородный пергамент с затемнёнными краями;
- чернильные рамки и тонкие разделители, небольшие угловые украшения;
- антиква, крупные числа и небольшие выразительные иконки;
- верхняя полоса имени и ключевых показателей;
- большой цветной портрет слева, характеристики и навыки справа;
- отдельная таблица атак: название, бонус, урон, тип;
- самостоятельные секции способностей, снаряжения и заметок;
- переменный классовый ресурс: Фортуна, Ци, Мицелий либо отсутствие ресурса.

Ни на одной извлечённой карточке нет первого Воина. Поэтому использован декоративный слот со щитом и мечами, **без придуманного портрета героя**. Его можно заменить собственным изображением. Карточки целиком, их текстуры, чужие портреты и надписи не встроены в сайт.

## Выбранные решения

| Наблюдение / задача                          | Решение в Эйдосе                                                                                             |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| На листе быстро читаются основные показатели | HP, Защита, скорость и кошелёк вынесены наверх                                                               |
| D&D Beyond отделяет действие от подробностей | Крупные кнопки характеристик и атак; длинные объяснения в раскрываемых секциях                               |
| Бросок должен показывать происхождение числа | Натуральные кубики, модификатор и итог разделены; при помехе видны оба кубика и выбранный минимум            |
| Атака и урон — связанные, но разные действия | Подтверждение попадания → отдельный бросок урона → подтверждение триггера                                    |
| Журнал не должен затмевать игру              | До десяти записей; последний результат выделен отдельно                                                      |
| Зависимые числа должны обновляться вместе    | Стойка одновременно меняет Защиту, оружие, атаки и реакцию                                                   |
| Не все действия всегда доступны              | Явные доступно/потрачено, disabled-состояния и текст причины блокировки                                      |
| Разные герои имеют разные механики           | Общие типы и UI отделены от модуля Воина                                                                     |
| Планшет — цифровой аналог листа              | Портрет слева, игровые блоки справа; результат и история ниже, без пропорций A4                              |
| Телефону нужен другой порядок                | Основные показатели, характеристики и бой выше портрета; нижняя навигация и немедленный компактный результат |

Мобильный и планшетный паттерны — собственная адаптация под ТЗ, проверенная в браузере. Не утверждается, что они повторяют недоступную нынешнюю мобильную версию D&D Beyond.

## Визуальный перевод

Текстура сделана процедурно в CSS/SVG, а не взята с карточки. Тонкие двойные края, малые ромбы, антиква, чернильные таблицы и большой левый портретный блок сохраняют связь с оригинальными листами. Активная стойка окрашена в приглушённый зелёный, коричневый или терракотовый; подпись «Активна» и `aria-pressed` дублируют цветовой сигнал. Результат кубиков выглядит отдельной частью листа, а не браузерным уведомлением.

## Продолжение: Смарчок и физические кубики

Предоставленная карточка Смарчка (`Смарчок.pdf`, встроенное изображение 1024 × 1536) стала основным визуальным эталоном: портрет занимает левую часть, справа — две колонки характеристик и навыков, ниже — способности и хранилище. Это изображение используется только в области портрета с SVG clipPath. Пергамент, границы, подписи, поля и действия реализованы HTML/CSS. Пустые игровые значения оставлены пустыми; явные бонусы навыков перенесены буквально.

Для 3D изучены README и исходники официального `@3d-dice/dice-box` 1.1.4:

- https://github.com/3d-dice/dice-box
- https://raw.githubusercontent.com/3d-dice/dice-box/main/src/WorldFacade.js
- npm-пакет 1.1.4, исходники в source maps и `dist/Dice.js`

Библиотека использует Babylon.js, Ammo WASM и worker физики. `roll()` возвращает отдельные физические кубики после остановки; их значения считываются ray casting из collider face map. Версия npm проверена напрямую, поскольку README содержит устаревший пример конструктора: используется актуальный объект конфигурации. Встроенный fallback без WebGL мог бы молча вернуть RNG; приложение заранее проверяет WebGL и отклоняет такой бросок с объяснением. WASM, модели и текстуры размещены на том же сайте, с учётом Vite base для GitHub Pages.

Свободный лоток постоянно доступен. Подробности, история, журнал и инвентарь перенесены в тематические окна с Escape и возвратом фокуса. На мобильном портрет кадрируется, карточка становится одной колонкой. Оба персонажа используют общий редактируемый фундамент, но Мицелий и боевые стойки сохраняются в разных механических модулях.
